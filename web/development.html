DEPLOY / OPERATE / VERIFY

A repeatable development environment.

One gateway, four independent CockroachDB stores, four OPA engines, one thin API/coordinator and an OpenTelemetry collector. All editable sources are included.

Quick start

unzip sovereign-federation-lab.zip
cd sovereign-federation-lab
./lab doctor
./lab up
# Open http://localhost:8080
./lab smoke
./lab test

Docker Engine or Desktop with Compose v2 is required. Allow 8 GB Docker memory and 10 GB free disk. On Windows, use WSL2 or a Bash terminal with Docker available. No host Python or Node install is needed for the container workflow. Image/package downloads require network access on first build.

Use cp .env.example .env to change LAB_PORT or COMPOSE_PROJECT_NAME. ./lab down preserves volumes. ./lab reset --confirm-synthetic-lab deletes this project's data and telemetry volumes.

Run the scenarios

./lab generate --count 5 --scenario sg-uk-no-us
./lab business --command open_holding --count 2
./lab migration-traffic --kind update --count 20 --interval 0.5
./lab migrate --reset
./lab sql IN -e 'SELECT owner,kind,count(*) FROM mig_rows GROUP BY owner,kind'
./lab logs monitor otel-collector

The original 30-entity directory uses SG, UK and US. Mumbai is provisioned as the fourth physical store for the isolated relocation slice. Its temporary SG permission is hypothetical and controlled by a manual deadline, not an assertion about current law. Migration preserves keys but does not yet move the original normalized business.* dataset.

Container topology and access

The browser accesses the gateway on host loopback. Static documentation and the monitor share the same origin. The gateway proxies /api/ and /api-docs to the monitor service. Business and control adapters connect only to their configured stores and OPA endpoints. This is a local deployment topology; the regional production service topology remains documented separately.

For a remote development VM keep the binding on loopback and use ssh -L 8080:127.0.0.1:8080 user@dev-host. Open localhost:8080 on your workstation. Do not expose this unauthenticated, insecure-SQL synthetic lab as a bank service.

Verification and remaining gates

The local structural/engine/Rego suites are recorded in TESTING.md. The container acceptance suite checks actual CockroachDB identity, OPA, gateway routes, business projections, migration SQL contents, restart persistence and Collector span receipt. It refuses a simulated or alternate database backend.

Docker is unavailable in the authoring environment. Container acceptance is supplied as an executable gate and GitHub Actions workflow; it has not been passed here. Earlier SQLite adapter results are historical unit evidence and are not CockroachDB validation. Browser-rendered visual QA also remains outstanding.

./lab test modifies synthetic data and resets only the migration namespace for its relocation test. It leaves base volumes intact and restarts the API for persistence verification. Check logs when a gate fails; the helpers never replace CockroachDB with SQLite.

Repository and source

The complete lab has a private Sites Git source repository. Download the source ZIP for deployment or the Git bundle for a portable clone with its initial commit. All design generators, ADR records, fixture data, previous model outputs and tests are included. Credentials, runtime database files and telemetry output are excluded.
