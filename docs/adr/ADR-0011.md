# ADR-0011: Source-writable copy followed by fenced cutover

Recorded: 11 October 2026. Retrospective project decision; not a bank governance approval.

## Status

Accepted; isolated migration implemented

## Context

Adding Mumbai should move an India entity without pausing its business operations for the entire copy.

## Decision

Capture a consistent snapshot and continuous changes, copy bounded batches, reconcile versions/tombstones/closure, then fence the old writer. Persist the new route as ACTIVATING before enabling the new epoch. Cleanup follows separately.

## Alternatives

Fence before the entire bulk copy; uncontrolled dual writer; change store_id without moving records.

## Consequences

A short entity-specific write pause is explicit. A new source write invalidates validation. After target writes there is no automatic route flip-back. The slice uses typed envelopes, not a migration of the normalized business.* tables; its control row remains in SG.

## Evidence

poc/migration.py; poc/policies/migration.rego; MIGRATION.md

## Gate

CockroachDB cutover/restart tests plus competing-controller/partition tests before pilot. Deadline expiry cannot create an implicit policy extension.
