# ADR-0018: A base customer MDM with system and experience APIs

Recorded: 14 October 2026. Pilot integration decision; not a bank governance approval.

## Status

Implemented synthetic single-host integration; bank pilot approval remains separate

## Context

A runnable baseline is needed to test system/customer integrations and caller-specific experiences against actual sovereignty controls.

## Decision

Keep business.party as the authoritative party and add owner-qualified source references and idempotent receipts in CockroachDB. Expose distinct authenticated system and experience API contracts. New identities default to owner-only; eligible minimums and relationship sharing use explicit synthetic profiles. Use separate mTLS recipient peers with current source/recipient OPA admission, exact envelope checks, scoped manifests, exact imported field sets and durable receipts. Keep HTTP delivery outside the owner business transaction and coordination lock; coalesce current-state delivery intents by scope/recipient while retaining business audit and fencing later restrictions; preserve the original lab as a separate trusted operator interface. Add a modern customer workspace backed by a bounded owner/source-qualified directory, keyset pagination and the existing system/experience contracts. The directory remains system-only; recipient identities can look up only authorised customer views. Clear previous identity data and fence late responses when credentials change. Show actual returned owner/projection sources, scope versions and trace evidence.

## Alternatives

Introduce an unrelated golden-record database; use a mocked business store or browser model as pilot evidence; treat a global ID as access to all relationships; send arbitrary raw CDC to foreign stores; couple peer acknowledgement to the business commit.

## Consequences

The pilot makes exact source-reference identity, SQL transactions, routed views, typed contracts and authenticated transport executable. Local test tokens/certificates and the shared host do not establish bank identity, physical residency or production isolation. Point reads, admission and relay use bounded scoped queries; broad base commands, monitoring and source-wide background work still need production capacity design. One source coordinator and synchronous read authority remain, with no offline lease. Normalized-table migration, MDM survivorship/merge governance and measured scale remain separate gates. ADR-0019 records the follow-on isolation, credential, protocol and independent-service foundations. The directory defaults to 25 records and caps pages at 50 with an 80-character query; page counts are not global totals. The UI adds no fuzzy matching, survivorship, quality score, merge/split or enterprise identity claim.

## Gate

Run real SQL/OPA system/experience API acceptance, default-deny and exact US minimum assertions, stale/replay/freshness tests, real peer/source/recipient OPA/Collector outages, process restart, trace-correlated logs, table/resource processing exclusions, filtered command receipts, real source/recipient field-catalog skew and readable narrowed imports without restoring policy, healthy-peer retry fairness and the browser workflow. Preserve every original lab gate. Approve real regional identity/infrastructure, retention, migration and workload evidence before using bank data. Verify actual SQL directory source isolation, paging and restart persistence, plus full US minimum/exclusion, role-safe browser profiles, real contact commands and real API outage recovery.
