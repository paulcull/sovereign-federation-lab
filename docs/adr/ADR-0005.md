# ADR-0005: One local ACID business boundary

Recorded: 11 October 2026. Retrospective project decision; not a bank governance approval.

## Status

Accepted; Python harness implemented, Spring Boot consolidation is pilot work

## Context

The bank wants fewer service handoffs and coherent transactions across related business modules.

## Decision

Co-locate participating business modules in one regional transaction boundary where invariants require it. Commit changed rows, sovereignty effects, outbox/audit intents and idempotency receipts locally. Remote copies are asynchronous.

## Alternatives

A synchronous distributed transaction across regions; a transaction per former microservice boundary.

## Consequences

Regional service availability and latency avoid a WAN quorum on every business command. Remote projections can lag and need explicit read freshness and policy guards.

## Evidence

poc/operational.py; poc/operational_schema.sql; design/src/operational_update.py

## Gate

Rollback must include business and outbox rows; retry must not duplicate effects. Measure the consolidated Java implementation separately.
