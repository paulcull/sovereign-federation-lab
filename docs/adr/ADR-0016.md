# ADR-0016: A development gateway with explicit production boundary

Recorded: 11 October 2026. Retrospective project decision; not a bank governance approval.

## Status

Accepted; local HTTP gateway implemented

## Context

The lab should have one entry point for UI, design pages and business/control APIs.

## Decision

Use an Nginx gateway bound to host loopback, serving the lab portal and proxying /api/ to the single harness. Regional authenticated business gateways remain a target deployment design.

## Alternatives

Expose SQL/OPA directly to the user; describe distributed gateways as already implemented.

## Consequences

Local HTTP and insecure SQL are synthetic-lab conveniences. Access from a remote workstation should use an SSH tunnel; bank use requires approved TLS, identity, authorization and regional ingress. Public assets and live-mode JSON must be readable by Nginx workers, and .mjs must use a JavaScript MIME type. Local health requests bypass host proxy settings.

## Evidence

infra/nginx.conf; infra/Gateway.Dockerfile; compose.yaml

## Gate

Gateway readiness and API routes work; only the gateway port is published; remote deployment runbook distinguishes tunnel access from production exposure.
